# Mine-imator Project Documentation

## Overview
Mine-imator is an advanced Minecraft animation software. This repository contains the source code for the application, which uses a unique hybrid architecture.

## Architecture
The project is split into two main components:

1.  **GmProject**: The core logic and assets of the application, written in GameMaker Language (GML). This is where most of the application's behavior, UI logic, and rendering logic reside.
2.  **CppProject**: The C++ hosting environment. This provides the windowing system, low-level rendering context (Qt/OpenGL), and the runtime environment for the translated GML code.
3.  **CppGen**: A custom transpiler written in C# (.NET 8.0) that converts the GML code from `GmProject` into C++ code that can be compiled as part of `CppProject`.

## Directory Structure
*   `GmProject/`: Contains the GameMaker Studio 2 project files.
    *   `scripts/`: GML scripts (functions).
    *   `objects/`: GameMaker objects (converted to C++ classes/structs).
    *   `sprites/`: UI and texture assets.
    *   `shaders/`: GLSL ES shaders.
    *   `datafiles/`: External data files loaded at runtime (languages, resources, etc.).
*   `CppProject/`: The C++ codebase.
    *   `Generated/`: Destination for C++ files generated by CppGen (do not edit these manually).
    *   `Asset/`: Contains headers and implementations for asset handling (Sprites, Shaders).
    *   `AppWindow.cpp`: Main window management using Qt.
    *   `Render/`: Rendering system integration.
*   `CppGen/`: The source code for the GML-to-C++ transpiler.
    *   `CppGen/Program.cs`: Entry point.
    *   `CppGen/GML.cs`: GML parser.
    *   `CppGen/CodeWriter.cs`: C++ code generator.

## The Transpilation Process
When `CppGen` runs:
1.  It reads `gml.json` to understand built-in GML functions and variables.
2.  It parses the `.yyp` project file in `GmProject`.
3.  It converts GML scripts and objects into C++ files in `CppProject/Generated`.
4.  It copies/updates Sprites and Shaders to `CppProject/Asset`.
5.  It generates `Mappings.cpp` to register all assets and functions in the C++ runtime.

## Development Workflow
To make changes to the application:
1.  **Logic Changes**: Edit GML files in `GmProject` using GameMaker or a text editor.
2.  **Engine Changes**: Edit C++ files in `CppProject`.
3.  **Build**: Run `CppGen` to update the generated C++ code, then compile `CppProject`.

## Localization
Localization strings are stored in `GmProject/datafiles/Data/Languages/`. The default language is defined in `GmProject/scripts/macros/macros.gml`.

## Continuous Integration
The project uses GitHub Actions (`.github/workflows/release.yml`) to automatically build and package releases for Windows, Linux, and macOS.
